# Sonarr Metadata Proxy

A lightweight metadata proxy for [Sonarr](https://sonarr.tv) that allows Sonarr to use alternative metadata sources such as **TMDB**, **MAL**, **AniList**, **TVMaze**, **AniDB**, while maintaining compatibility with **TVDB/SkyHook**.

The proxy runs alongside an existing Sonarr installation and does **not require a modified Sonarr image or Sonarr fork**.

## Features

- **Multiple metadata sources** — pick TMDB, TVDB, AniList, MAL, TVMaze, or AniDB per series via the **Metadata source** dropdown, or per search via **Search via**.
- **Anime-ready** — AniList/MAL/AniDB resolve to a single continuous season; no mixed artwork (AniList uses its own posters/banners, MAL pulls backgrounds from Tenrai).
- **Reset series to TVDB** — one button wipes all provider IDs, episode mappings and overrides, pins the series to TVDB and triggers a Sonarr **Refresh & Scan** to re-fetch cleanly.
- **Resolver auditing** — see exactly why a series resolved to a show/episode list (diagnoses wrong-show lookups).
- **AniDB poster proxy** — posters are proxied through the container's own endpoint to bypass cdn hotlink blocking (browsers that send a Referer get blocked by AniDB otherwise).
- **Log sanitization** — all user input in log sinks is sanitized to prevent log forging.
- **Drop-in** — mounts a CA cert and patches Sonarr's UI via a shared folder; Sonarr resolves `skyhook.sonarr.tv` to the proxy. Works with stock Sonarr and Docker UIs (Synology, Portainer, Dockhand, ...).

## How It Works

Sonarr normally communicates with `skyhook.sonarr.tv` for metadata.

The proxy uses a Docker network alias for `skyhook.sonarr.tv`, allowing the request to be handled by the proxy before being forwarded to the selected metadata provider.

Sonarr therefore continues to operate normally while the proxy handles the metadata request and converts the provider response into the format expected by Sonarr.

## Usage

The proxy is designed to run alongside your existing Sonarr container.

Both containers must be connected to the same Docker network, with the proxy using the following network alias:

```yaml
networks:
  arrnet:
    aliases:
      - skyhook.sonarr.tv
```

### Docker Compose

```yaml
services:

  sonarr:
    image: lscr.io/linuxserver/sonarr:latest
    container_name: sonarr

    volumes:
      - /path/to/sonarr/config:/config
      - /path/to/tvseries:/tv
      - /path/to/downloads:/downloads
      - certs:/shared/certs:ro

    ports:
      - 8989:8989

    networks:
      - arrnet

    restart: unless-stopped

  sonarr-metadata-proxy:
    image: crisperfx/sonarr-metadata-proxy:latest
    container_name: sonarr-metadata-proxy

    environment:
      - ASPNETCORE_ENVIRONMENT=Production

    env_file:
      - .env

    volumes:
      - proxy-data:/app/data
      - certs:/app/data/certs

    ports:
      - 9697:9697

    cap_add:
      - NET_BIND_SERVICE

    networks:
      arrnet:
        aliases:
          - skyhook.sonarr.tv

    restart: unless-stopped

volumes:
  proxy-data:
  certs:

networks:
  arrnet:
    driver: bridge
```

## Configuration

Configuration can be provided through environment variables or a `.env` file. **All defaults below are pre-baked into the image**, so a container works out of the box. Only `TMDB_API_KEY` (or `TMDB_API_TOKEN`) and `CORS_ALLOWED_ORIGINS` need your own values.

Example `.env`:

```env
# Primary metadata source used by the proxy (tmdb | tvdb | anilist | mal | tvmaze | anidb | imdb)
METADATA_SOURCE=tmdb

# TMDB credentials: EITHER the v3 API key OR the v4 bearer token. You need at least one.
# If both are set, the bearer token wins. Get them at https://www.themoviedb.org/settings/api
TMDB_API_KEY=your-tmdb-v3-api-key
TMDB_API_TOKEN=

# Optional AniDB HTTP API credentials (for the AniDB provider / anidb: prefix).
# Required to use AniDB as a search or per-series metadata source; leave blank to disable.
# Register this client name + version at https://anidb.net/software/add ; you must set BOTH.
ANIDB_CLIENT=
ANIDB_CLIENT_VERSION=

# Optional: browser-reachable base URL of this proxy (e.g. http://192.168.1.50:9697).
# When set, AniDB posters are served through the proxy's own image proxy endpoint
# instead of directly from cdn.anidb.net, because AniDB blocks browsers that send a
# Referer (hotlink protection). Leave blank to use the direct cdn.anidb.net URLs.
ANIDB_IMAGE_BASE_URL=

# Optional: language requested from TMDB (default en-US)
TMDb_LANGUAGE=en-US

# When a series cannot be mapped or the source API fails, fall back to the real SkyHook/TVDB.
ENABLE_TVDB_FALLBACK=true

# Management/health HTTP port (the SkyHook/TLS listener is always on port 443)
PORT=9697

# Log level for the proxy (Trace | Debug | Information | Warning | Error)
LOG_LEVEL=Information

# How long successful responses are cached, in minutes (default 1440 = 24h)
CACHE_TTL_MINUTES=1440

# Maximum number of search results returned per provider
SEARCH_RESULT_LIMIT=10

# Directory that holds the AniList datamap export
ANILIST_DATAMAP_DIR=datamaps

# Set to true to disable the TLS listener (443) and run plain HTTP only. NOT for use with Sonarr.
SKIP_TLS=false

# Real SkyHook base URL used only for the TVDB fallback / passthrough.
SKYHOOK_BASE_URL=https://skyhook.sonarr.tv

# DNS-over-HTTPS endpoint used to resolve SKYHOOK_BASE_URL (avoids the Docker network
# alias answering for skyhook.sonarr.tv and a hardcoded IP).
SKYHOOK_RESOLVER_URL=https://cloudflare-dns.com/dns-query

# CORS origins allowed to call the /api/overrides management API from a browser.
# Required only for the optional in-Sonarr picker (init/50-sonarr-override-ui.sh).
# Use the exact origin as seen in your browser, e.g. http://192.168.1.10:8989. "*" allows any.
# Behind an HTTPS reverse proxy (e.g. Synology): CORS stays the browser origin of Sonarr
# (e.g. https://sonarr.example.com), but you must ALSO set OVERRIDES_API_URL on the
# Sonarr container so the picker talks to the proxied API (see README, reverse proxy).
# Leave empty to disable CORS.
CORS_ALLOWED_ORIGINS=

# Data directory (mapping store + generated CA/certificates). Mounted as a volume in Docker.
DATA_DIR=/app/data
```

### Metadata Sources

Supported metadata sources include:

- `tmdb`
- `anilist`
- `mal`
- `tvmaze`
- `anidb`
- `tvdb` (passthrough)

A global metadata source can be configured while individual series can use their own provider.

**All credentials are optional** — only provide keys for the providers you actually use:
- `TMDB_API_KEY` / `TMDB_API_TOKEN` — only needed if using TMDB
- `ANIDB_CLIENT` + `ANIDB_CLIENT_VERSION` — only needed if using AniDB (register at <https://anidb.net/software/add>)
- AniList, MAL, TVMaze, TVDB require no API keys

## Ports

| Port | Purpose |
|---|---|
| `443` | HTTPS endpoint used for Sonarr/SkyHook traffic |
| `9697` | Management API and metadata configuration |

Port `443` is normally used internally between the Sonarr and proxy containers and does not need to be published on the Docker host.

Port `9697` can be exposed when the management API is required by the Sonarr UI or through a reverse proxy.

## Volumes

| Container Path | Description |
|---|---|
| `/app/data` | Persistent proxy configuration and metadata mappings |
| `/app/data/certs` | Generated CA certificate data |

Per-series provider mappings are stored in:

`/app/data/mappings/mappings.json`

Make sure `/app/data` is backed by a persistent Docker volume.

## Sonarr Integration

The proxy is designed to work with the standard Sonarr Docker image.

No modified Sonarr image is required.

During startup, the required integration scripts can:

- Install the proxy CA certificate into Sonarr
- Configure Sonarr to trust the proxy HTTPS endpoint
- Provide the metadata-source selection interface (dropdown in Sonarr UI)

The underlying Sonarr installation remains unchanged.

## HTTPS / Reverse Proxy

When Sonarr is accessed through HTTPS, the proxy API should also be available through HTTPS when required by the browser-based integration.

Example:

```env
OVERRIDES_API_URL=https://proxy.example.com
CORS_ALLOWED_ORIGINS=https://sonarr.example.com
```

## Updating

Pull the latest image and recreate the container:

```bash
docker pull crisperfx/sonarr-metadata-proxy:latest
docker compose up -d
```

Persistent data stored in `/app/data` is retained when the container is recreated.
